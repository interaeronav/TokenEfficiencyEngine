# Unreal Automation Surfaces

*Deep-research digest, 2026-08-21. Part of the TEE research corpus — see [00-index.md](00-index.md).*

## Summary

UE5 offers four practical external-automation surfaces: (1) the Python Editor Script Plugin (Python 3.11.8 in UE 5.4+, editor-only, reflects nearly the entire Blueprint-exposed API, with a UDP-multicast remote-execution channel on `239.0.0.1:6766` that most existing Unreal MCP servers use), (2) the Remote Control plugin's HTTP (port `30010`) + WebSocket (port `30020`) servers with generic `/remote/object/call` / `property` / `describe` / `batch` endpoints plus curated Presets, (3) headless commandlets (`-run=pythonscript`, `ResavePackages`, `cook`, `Automation RunTests`) for CI-style batch work, and (4) editor-only C++ libraries.

Blueprint *asset* creation, component/variable manipulation, and compilation are reachable from Python (`BlueprintFactory`, `SubobjectDataSubsystem`, `unreal.BlueprintEditorLibrary`), but K2Node graph authoring is NOT reflection-exposed — every MCP project that wires Blueprint graphs ships a custom C++ editor plugin speaking JSON over a local TCP socket.

Verse remains UEFN/Fortnite-only (converging into UE6 as the Scene Graph scripting layer); UEFN itself gained experimental Python editor scripting in the March 2026 v40.00-era update, explicitly citing MCP/agentic AI remote execution as a use case. Live Coding (Live++) has no documented external trigger; the practical hook is issuing its console command through Remote Control or Python.

For a token-efficiency engine, the highest-leverage design is a thin typed tool surface over Remote Control presets + batched Python execution, avoiding raw `/remote/object/describe` dumps which are extremely verbose.

## Findings

### Python scripting: plugin and version

Plugin name: "Python Editor Script Plugin" (enable per-project under Edit > Plugins > Scripting); companion plugin "Editor Scripting Utilities" adds simplified APIs. The embedded interpreter is Python 3.11.8 in current docs (5.4–5.8), chosen to match the VFX Reference Platform (UE 5.0–5.3 shipped Python 3.9.7). The `unreal` module is generated by reflection: it exposes "nearly everything that is exposed from C++ to Blueprints", including plugin and project C++ APIs, with automatic snake_case renaming and type conversion.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python)

### Python scripting: editor-only restriction

The Python environment is "only available in the Unreal Editor, not when your Project is running in the Unreal Engine in any mode" — no PIE-runtime standalone, no cooked/shipped builds; it cannot be a gameplay scripting language. Editor-module functions are callable only from editor contexts (Editor Utility Widgets/Blueprints, not runtime Actor classes).

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python)

### Python scripting: execution entry points

Entry points:

1. In-editor Python console / `py <script>` Cmd command.
2. `init_unreal.py` auto-executed from any configured Python path (`Content/Python` of project, engine, enabled plugins, or `Documents/UnrealEngine/Python`).
3. Project Settings > Plugins > Python > Startup Scripts.
4. Command line `UnrealEditor.exe project.uproject -ExecutePythonScript=script.py` (full editor boots, runs script, exits).
5. Commandlet `UnrealEditor-Cmd.exe project.uproject -run=pythonscript -script=script.py` (headless, fast, no level auto-loaded — must load assets/levels manually).
6. `-ExecCmds="py script.py"`, which leaves the editor interactive.

Add `-stdout -FullStdOutLogOutput` to capture log output. The editor can be closed from script via `unreal.SystemLibrary.execute_console_command(None, 'QUIT_EDITOR')`.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python) and [https://www.xingyulei.com/post/ue-commandline-python/index.html](https://www.xingyulei.com/post/ue-commandline-python/index.html)

### Python scripting: key utility classes

`unreal.EditorAssetLibrary` (asset CRUD), `unreal.AssetTools`, `unreal.ScopedEditorTransaction` (undo/redo batching), `unreal.ScopedSlowTask`, and editor subsystems via `unreal.get_editor_subsystem()` (e.g. `EditorActorSubsystem`, `LevelEditorSubsystem`, `SubobjectDataSubsystem` — subsystems replaced the deprecated `EditorLevelLibrary` monolith during UE5). Properties should be set via `set_editor_property()`/`get_editor_property()` so `PreEditChange`/`PostEditChange` callbacks fire.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python)

### Python scripting: remote execution channel (critical for MCP bridges)

The Python plugin has a built-in "remote execution" feature (enabled in Project Settings > Python): the editor listens on UDP multicast group `239.0.0.1:6766` for node discovery, then opens a TCP command channel (default TCP `6776`) to execute Python strings/files remotely. This is what the Epic VS Code extension and community wrappers (`upyrc` on PyPI, `radial-hks/MCP-Unreal-Server`) use. The firewall must allow UDP `6766` + TCP `6776`. This lets an external MCP process inject arbitrary Python without any plugin installed in the project beyond the stock Python plugin.

Source: [https://pypi.org/project/upyrc/](https://pypi.org/project/upyrc/) and [https://github.com/radial-hks/MCP-Unreal-Server](https://github.com/radial-hks/MCP-Unreal-Server)

### Remote Control: servers, ports, enablement

The Remote Control plugin (Beta) runs an in-engine web server: HTTP REST on port `30010` and WebSocket on `ws://127.0.0.1:30020` (both configurable via Project Settings > Web Remote Control, `URemoteControlSettings` class in plugin `RemoteControlCommon`). Start/stop via console commands `WebControl.StartServer` / `WebControl.EnableServerOnStartup`. Default bind address is `127.0.0.1` (localhost-only); `DefaultBindAddress` is changeable in `DefaultEngine.ini`. Recent versions require/support a passphrase header (implemented in `WebRemoteControl.cpp`; poorly documented). Epic explicitly warns never to expose the port to the open Internet — LAN/VPN only.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-quick-start-for-unreal-engine](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-quick-start-for-unreal-engine) and [https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Plugins/RemoteControlCommon/URemoteControlSettings](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Plugins/RemoteControlCommon/URemoteControlSettings)

### Remote Control: generic HTTP endpoints

Routes:

- `GET /remote/info` — lists all routes.
- `OPTIONS /remote` — CORS.
- `PUT /remote/object/call` `{objectPath, functionName, parameters, generateTransaction}` — calls any Blueprint-callable `UFunction` on any `UObject`.
- `PUT /remote/object/property` `{objectPath, propertyName, access: READ_ACCESS|WRITE_ACCESS|WRITE_TRANSACTION_ACCESS, propertyValue}` — property must be public, non-const, no `BlueprintGetter`/`BlueprintSetter`.
- `PUT /remote/object/describe` `{objectPath}` — full metadata dump of properties/functions.
- `PUT /remote/object/thumbnail`.
- `PUT /remote/search/assets` `{Query, Filter:{PackageNames, ClassNames, PackagePaths, RecursivePaths, RecursiveClasses, RecursiveClassesExclusionSet}}` — Asset Registry search.
- `PUT /remote/batch` `{Requests:[{RequestId, URL, Verb, Body}]}` — multiple requests in one HTTP call.
- `PUT /remote/object/event` (experimental, requires ini cvar `WebControl.EnableExperimentalRoutes=1`) for `ObjectPropertyChanged` long-polling.

ObjectPath format: `/Game/Map.Map:PersistentLevel.ActorName` (PIE adds the `UEDPIE_0_` prefix; CDOs are `/Script/Module.Default__Class`).

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-http-reference-for-unreal-engine](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-http-reference-for-unreal-engine)

### Remote Control: preset endpoints (curated surface)

Remote Control Presets are editor-authored assets exposing a chosen subset of properties/functions with labels, groups, and metadata. HTTP routes:

- `GET /remote/presets`
- `GET /remote/preset/{name}` — returns Groups with `ExposedProperties`/`ExposedFunctions` incl. types and metadata.
- `GET|PUT /remote/preset/{name}/property/{prop}` — `{PropertyValue, GenerateTransaction}`.
- `PUT /remote/preset/{name}/function/{func}` — `{Parameters, GenerateTransaction}` → `{ReturnedValues}`.
- `GET/PUT/DELETE /remote/preset/{name}/metadata[/{key}]` — arbitrary key-value metadata.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-preset-api-http-reference-for-unreal-engine](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-preset-api-http-reference-for-unreal-engine)

### Remote Control: WebSocket messages and change events

WebSocket messages are JSON with `MessageName`: `http` (tunnels any HTTP route through the socket, with optional `Id` for correlating responses), `preset.register`/`{PresetName}` and `preset.unregister`. After `preset.register` the client receives push events: `PresetFieldsChanged` (property value changed, includes `PropertyLabel`/`ObjectPath`/`PropertyValue`), `PresetFieldsAdded`, `PresetFieldsRemoved`, `PresetFieldsRenamed` (`OldFieldLabel`/`NewFieldLabel`). This is the only documented push-notification channel — the generic object surface has no subscription except the experimental `/remote/object/event` route.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-websocket-reference-for-unreal-engine](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-websocket-reference-for-unreal-engine)

### Commandlets and headless automation

Any commandlet runs via `UnrealEditor-Cmd.exe <project.uproject> -run=<CommandletName> [args]` in a raw environment (no client, no level loaded, no actors). Key commandlets: `pythonscript` (headless Python with full `unreal` module), `ResavePackages` (batch resave; flags `-BuildLighting`, `-AllowCommandletRendering`, `-MapsOnly`, `-ProjectOnly`, `-Map=Name`), `cook`, `DerivedDataCache`. Useful flags: `-NoShaderCompile`, `-unattended`, `-nullrhi`, `-nosplash`, `-stdout`, `-FullStdOutLogOutput`. The Automation test framework runs headless via `-ExecCmds="Automation RunTests <filter>"`. Higher-level orchestration is Unreal Automation Tool (UAT, `RunUAT.bat BuildCookRun`) and UnrealBuildTool (UBT) for compiles.

Source: [https://dev.epicgames.com/documentation/unreal-engine/unreal-automation-tool-overview-for-unreal-engine](https://dev.epicgames.com/documentation/unreal-engine/unreal-automation-tool-overview-for-unreal-engine) and [https://zomgmoz.tv/unreal/Building-and-Packaging/ResavePackages-Commandlet](https://zomgmoz.tv/unreal/Building-and-Packaging/ResavePackages-Commandlet) and [https://en.imzlp.com/posts/27475/](https://en.imzlp.com/posts/27475/)

### Blueprint automation: what Python CAN do

From Python you can: create Blueprint assets (`unreal.BlueprintFactory` + `AssetTools`, `set_editor_property('parent_class', unreal.Actor)`); add/remove components via `unreal.SubobjectDataSubsystem` (UE 5.0+, the supported path; community forum threads document handle pitfalls); compile Blueprints and edit variables via `unreal.BlueprintEditorLibrary` (exists in Python API docs for 5.0, 5.1, 5.6 — functions include `compile_blueprint`, plus variable/reference utilities; C++ class `UBlueprintEditorLibrary` in the `Editor/BlueprintEditorLibrary` module). CDO property edits work via normal property access.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/BlueprintEditorLibrary?application_version=5.6](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/BlueprintEditorLibrary?application_version=5.6) and [https://forums.unrealengine.com/t/python-trying-to-create-subobject-in-blueprint-getting-not-valid-handles/855866](https://forums.unrealengine.com/t/python-trying-to-create-subobject-in-blueprint-getting-not-valid-handles/855866)

### Blueprint automation: what Python CANNOT do — node graphs need C++

K2Node graph authoring (`UK2Node_CallFunction`, `UK2Node_Event`, `UEdGraph` pin wiring) lives in editor-only C++ modules (`BlueprintGraph`, `UnrealEd`, `Kismet`) that are NOT exposed to Blueprint reflection, hence invisible to the stock Python `unreal` module and to Remote Control. The dead `20tab/UnrealEnginePython` plugin could do it only because it bound C++ directly. Consequently every current Blueprint-graph MCP ships a custom C++ editor plugin:

- `chongdashu/unreal-mcp` — plugin "UnrealMCP", JSON over TCP port `55557`, UE 5.5+, experimental; tools for actors, Blueprint classes/components/compile, node graph event+function nodes, editor viewport.
- `lilklon/UEBlueprintMCP` — TCP/JSON port `55558`, UE 5.7+.
- `flopperam/unreal-engine-mcp` — full Blueprint lifecycle: variables/components/events/functions/graph wiring.
- `tumourlove/unreal-blueprint-mcp` — read-only graph introspection: nodes, pins, connections, execution flow.
- `remiphilippe/mcp-unreal` — 49 tools, UE 5.7, headless builds/tests + Blueprint editing.
- `syan2018/UnrealCopilot` — traces Blueprint↔C++↔Asset reference chains.

Source: [https://github.com/chongdashu/unreal-mcp](https://github.com/chongdashu/unreal-mcp) and [https://github.com/lilklon/UEBlueprintMCP](https://github.com/lilklon/UEBlueprintMCP) and [https://github.com/flopperam/unreal-engine-mcp](https://github.com/flopperam/unreal-engine-mcp) and [https://lobehub.com/mcp/tumourlove-unreal-blueprint-mcp](https://lobehub.com/mcp/tumourlove-unreal-blueprint-mcp) and [https://github.com/remiphilippe/mcp-unreal](https://github.com/remiphilippe/mcp-unreal)

### Blueprint introspection via Remote Control

`/remote/object/describe` returns any Blueprint instance's or CDO's reflected properties/functions (Name, Class, Type, Description, Metadata) without a plugin, and `/remote/object/call` can invoke any `BlueprintCallable` function including custom Blueprint functions — so behavior invocation and property-level introspection are possible externally; only graph structure read/write is closed. Blueprint `.uasset` files are binary and have no supported external text format (offline parsing exists only via third-party tools like UAssetAPI; graph copy/paste uses an undocumented T3D-like clipboard text format).

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-http-reference-for-unreal-engine](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-control-api-http-reference-for-unreal-engine)

### Verse: where it runs

Verse runs only inside UEFN/Fortnite Creative today — it is not a scripting surface in stock UE 5.3–5.8. Epic's stated direction (State of Unreal 2026, confirmed June 17, 2026): Verse becomes the foundation of Scene Graph, the gameplay framework replacing the Actor system in Unreal Engine 6, "transactionalizing C++", with Fortnite's ecosystem converging into UE6. UE 5.6 (mid-2025), 5.7 (released Nov 12 2025) and 5.8 do not expose Verse for game projects.

Source: [https://www.unrealengine.com/news/state-of-unreal-2026-top-news-from-the-show](https://www.unrealengine.com/news/state-of-unreal-2026-top-news-from-the-show) and [https://gamedev.net/news/4002/](https://gamedev.net/news/4002/)

### Verse/UEFN: external tool access

UEFN gained experimental "Python Editor Scripting" (early preview, enabled in Project Settings, ~March 2026 / Fortnite v40.00 era, Python 3.11). Epic's own docs list "Remote execution of well made scripts or tools, such as a MCP integration with an Agentic AI" as a supported use case. Restrictions: scripts may only modify properties allow-listed in UEFN (others fail validation), cannot place content absent from the UEFN content browser, cannot touch external project content. Verse source files (`.verse`) are plain text in the project folder — external tools can generate/edit them, but compilation and push happen only through the UEFN client. Community MCP servers exist (`KirChuvakov/uefn-mcp-server`: 22 tools for actors/assets/levels/viewport/Python exec; community listeners bind ports `8765`–`8770` HTTP), plus UEFN-TOOLBELT (287+ Python tools incl. Verse code generation).

Source: [https://dev.epicgames.com/documentation/fortnite/python-tools-in-uefn](https://dev.epicgames.com/documentation/fortnite/python-tools-in-uefn) and [https://github.com/KirChuvakov/uefn-mcp-server](https://github.com/KirChuvakov/uefn-mcp-server) and [https://forums.unrealengine.com/t/open-source-project-uefn-toolbelt-287-python-tools-for-world-building-verse-automation/2709005](https://forums.unrealengine.com/t/open-source-project-uefn-toolbelt-287-python-tools-for-world-building-verse-automation/2709005)

### Live Coding / hot reload

Live Coding (an integration of Live++) is enabled by default in UE5; triggered by Ctrl+Alt+F11 from IDE or editor; works in editor, PIE, and attached to packaged desktop builds; Windows-only in practice (unsupported on console/mobile). It patches function-body changes and header default-value changes; structural `UObject` changes require the "Object Reinstancing" setting; `.cpp`-constructor default values do NOT update existing instances; improperly dereferenced reinstanced objects can crash at shutdown (Hot Reload — the older, slower alternative — tolerates this better). Official docs document NO console variable, programmatic, or external-process trigger; external automation is limited to sending the editor's live-coding console command (e.g. via Remote Control `/remote/object/call` on `KismetSystemLibrary.ExecuteConsoleCommand` or via Python) or doing full UBT rebuilds with the editor closed. Community cvar wikis list `LiveCoding.*` console commands ([indxzero.github.io/ue544cvarwiki/articles/livecoding/](https://indxzero.github.io/ue544cvarwiki/articles/livecoding/)).

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime)

### Version differences summary (UE 5.3–5.6)

The Remote Control HTTP/WS API shape (routes, ports `30010`/`30020`) is stable across 5.2–5.8 docs (still Beta throughout); passphrase enforcement appears in later 5.x (surfaced in `WebRemoteControl.cpp`, tripping users on 5.4). Python: 3.9.7 in 5.0–5.3, 3.11.8 from 5.4 onward; the Python API remains labeled "Experimental" in docs through 5.6. `SubobjectDataSubsystem` exists from 5.0. Community MCP plugins segment by engine version: chongdashu targets 5.5+, lilklon and remiphilippe target 5.7+. Verse is absent from all 5.x; UE6 is the Verse/Scene Graph convergence point.

Source: [https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python](https://dev.epicgames.com/documentation/en-us/unreal-engine/scripting-the-unreal-editor-using-python) and [https://forums.unrealengine.com/t/things-to-know-about-the-remote-control-api/652426](https://forums.unrealengine.com/t/things-to-know-about-the-remote-control-api/652426)

## Recommendations for TEE

1. Use two transports, not one: Remote Control WebSocket (port `30020`) for structured, low-latency call/property operations and change-event push (`preset.register`), plus the Python remote-execution channel (UDP `239.0.0.1:6766` discovery + TCP `6776`) for anything the reflection surface can't do. Both work with zero custom plugin code in the user's project — a major adoption and maintenance win over the custom-TCP-plugin approach most existing UE MCPs take.
2. Token efficiency: never forward raw `/remote/object/describe` or preset detail JSON to the model — these dumps enumerate every reflected property with metadata and are enormous. Cache them server-side in TEE, and surface compact typed tool schemas (or a filtered field list on demand) instead.
3. Exploit `/remote/batch` (and the WebSocket `http` tunnel with `Id`s) to let one model tool-call perform N engine operations — design TEE tools as coarse-grained verbs (e.g. `spawn_and_configure_actor`) that expand into batched Remote Control requests server-side, so the model spends tokens on intent, not on per-property round trips.
4. For Blueprint work, split capability tiers honestly: Tier 1 (no plugin) — create Blueprint assets, add components (`SubobjectDataSubsystem`), set CDO properties, compile (`BlueprintEditorLibrary`), all via remote Python; Tier 2 (optional TEE C++ editor plugin) — K2Node graph authoring/introspection, since that is provably impossible through reflection. Consider generating C++ or Python-driven construction instead of Blueprint graphs where acceptable — text code is far more token-efficient than node-graph JSON.
5. Prefer executing generated Python scripts (sent as a single string over remote execution) over many fine-grained MCP calls: one script with `unreal.ScopedEditorTransaction` gives atomic undo, one round trip, and returns only a small result summary — dramatically fewer tokens than chatty per-call protocols.
6. Use commandlet mode (`UnrealEditor-Cmd -run=pythonscript -nullrhi -unattended -stdout -FullStdOutLogOutput`) for batch/CI jobs (asset validation, resaves, automation tests via `-ExecCmds="Automation RunTests"`) where no live editor is needed; parse and summarize the log server-side before anything reaches the model.
7. Author or auto-generate Remote Control Presets as the curated, labeled surface for scene manipulation: presets give short stable labels (cheap tokens), grouping, metadata key-values (usable to store TEE hints/descriptions), and the only reliable change-event subscription — ideal for keeping a differential world-state cache so TEE sends the model deltas, not full scene dumps.
8. Bind everything to `127.0.0.1`, handle the Remote Control passphrase header, and never expose ports `30010`/`30020`/`6766`/`6776` beyond localhost — Epic explicitly warns these servers are unauthenticated LAN-trust surfaces.
9. Treat Verse/UEFN as a separate adapter, not a UE5 feature: target UEFN's experimental Python Editor Scripting (which Epic explicitly blesses for MCP/agentic AI remote execution) plus text-based `.verse` file generation, and respect the allow-listed-property validation limits. Plan for UE6, where Verse/Scene Graph becomes the primary scripting surface.
10. Do not build on Live Coding for automated C++ iteration: it has no documented external trigger and crashes on bad reinstancing. Offer instead (a) a "request live compile" convenience that fires the editor console command via Remote Control, and (b) a robust closed-editor UBT rebuild path; keep AI-generated logic in Python/Blueprint tiers where hot iteration is safe.
