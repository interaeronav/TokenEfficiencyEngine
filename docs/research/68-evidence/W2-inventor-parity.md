## The gap worth building into

Inventor's automation surface, precisely:

1. **Desktop, Windows-only, COM.** Every write path (VBA, add-ins, standalone EXE, iLogic) is a COM Automation client of a running, licensed Inventor on Windows 10/11 64-bit (`API26/GettingStarted.htm`; release notes above). Autodesk's own blog: "there is no official Mac compatible version of Inventor" (https://www.autodesk.com/blogs/design-and-manufacturing/inventor-on-mac/). No Linux.
2. **Local headless = read-only or license-gated.** Apprentice Server is free and UI-less but "Access to the assembly structure, B-Rep, geometry and render styles is read-only" (`API26/Apprentice_Overview.htm`). The full headless engine (Inventor Server / `InventorCoreConsole.exe`) exists, but on the desktop it ships only inside the Vault Job Processor, for four job types, under terms limiting headless use to "automating that Vault product's functionality" and forbidding use in "a software product or service … licensed to a third-party" (Vault-Admin GUID-CDD7E780; Vault-Install GUID-30A964D6).
3. **Cloud headless = metered, capped, Windows sandbox.** The Automation API runs `InventorCoreConsole.exe` in Autodesk's cloud, "must only interact with the InventorServer object", low-privilege Windows, no Content Center / Frame Generator / Tube & Pipe / Design Accelerator (`DA/developers_guide/restrictions/`); 900 s default / 12 h max per WorkItem (`DA/developers_guide/rate-limits/da-rate-limits`); 300 free minutes/month then $3 per 12 processing minutes ≈ $15/h in Flex tokens, $99 minimum prepay (rate sheet URL above); engines retired 6 years after release (`DA/developers_guide/engine-lifecycle`); your script must be a .NET 8 add-in DLL or an iLogic file (.NET-8 blog above).
4. **LLM integration is in-app and 2027-only.** Autodesk Assistant lives as a dockable panel inside Inventor 2027 (tech preview), speaks MCP internally, and per Autodesk's developer blog "does not yet create or modify geometry directly"; Autodesk publishes MCP servers for Help, Fusion and Revit but none for Inventor (URLs in row F).

Why a headless-first, script-is-the-product, macOS/Linux-capable kernel is an inversion, not a clone (same logic as doc 67 §1 on Marvelous Designer's in-app, enterprise-tier API): in Inventor the GUI is the product and every headless route is a derivative of it — read-only (Apprentice), rented per minute in someone else's Windows sandbox (Design Automation), or licensed only as a Vault appendage (Inventor Server). A kernel whose primary surface *is* the script — parametric sketch + constraint solver, feature history, assembly joints/constraints, sheet-metal unfold rules, drawing generation, all callable from a plain process on any OS, with the GUI (if any) as one more client — puts the incumbent's secondary, gated surface at the centre and drops the licence/OS/metering walls entirely. That is exactly the shape TEE exists to drive (tokens-per-task, batched macro calls, diffs not dumps). Parity target = the loop **sketch → constrain/dimension → feature → assemble → drawing/flat pattern → export**, with A–E above as the checklist; F is the *contrast*, G is out of scope.

## IP guardrail

Feature parity is fine; the containers and the chrome are not. Implement open interchange only (STEP AP242/AP214, IGES, Parasolid-free B-rep via your own kernel or OCCT, STL/OBJ/glTF/3MF, DXF/DWG via open libraries, PDF). Do **not** reverse-engineer `.ipt/.iam/.idw/.ipn/.ide` (undocumented, proprietary; Autodesk's own sanctioned reader is Apprentice/Inventor on Windows), do not copy the ribbon/browser/property-panel chrome or icons, and do not reuse Autodesk marks ("Inventor", "iLogic", "iPart/iAssembly/iFeature/iMate", "AnyCAD", "Design Accelerator", "Content Center") as product or feature names. Do not redistribute Autodesk-shipped data (Thread.xls, Content Center libraries, sheet-metal bend tables, drawing templates/title blocks); regenerate equivalents from the public standards (ISO/ANSI/DIN tables) with their own citations.
