## Geometry metrics — verified tooling (ran, not recalled)

- **Watertightness rate**: `trimesh.Trimesh.is_watertight` (bool per mesh; rate over a fixed input set). Verified: True on clean icosphere, False on holed sphere / non-manifold fin. trimesh 5.0.0, MIT.
- **Boundary loops / hole count**: boundary edge count = edges appearing once via `trimesh.grouping.group_rows(mesh.edges_sorted, require_count=1)`; loop count = `len(mesh.outline().entities)`. Verified: holed sphere → 24 boundary edges, 1 loop; clean sphere → 0.
- **Non-manifold edge count**: count edges shared by >2 faces from `mesh.edges_sorted` (Counter over sorted edge tuples — ~5 lines, no extra dep). Verified: fin fixture → 1; clean → 0. Cross-check: `manifold3d.Manifold(...).status()` returns `manifold3d.Error.NotManifold` (vs `Error.NoError`); `.genus()` valid only on NoError. manifold3d 3.5.2, Apache-2.0.
- **Self-intersection count**: trimesh has no native check. Verified working: pymeshlab filter `compute_selection_by_self_intersections_per_face` → `selected_face_number()` (12/24 flagged on an interpenetrating two-box concat, 0 on a clean sphere). Caveats: pymeshlab is **GPL3** (dev-only eval dep, never linked into the shipped product) and needs libOpenGL for some plugins (this core filter worked without). Open3D's `is_self_intersecting()` rejected: 447.7 MB wheel — too heavy for CI.
- **Degenerate triangles**: `trimesh.triangles.nondegenerate(mesh.triangles, height=1e-8)` (caught both the zero-area dup-vertex face and the 1e-9 sliver; plain `area_faces < eps` caught only the zero-area one — use `nondegenerate`).
- **Euler characteristic sanity**: `mesh.euler_number` (2 per closed genus-0 component; verified 2 on sphere, 4 on two-component concat, 1 on holed sphere). Compute **per connected component** (`mesh.split()`), else multi-part outputs read as anomalies.
- **Watertight-but-interpenetrating trap (verified)**: the two-overlapping-boxes concat is `is_watertight=True`, `is_volume=True`, 0 boundary edges — watertightness alone misses interpenetration; the self-intersection metric is not optional.
- **UV overlap %**: load the product GLB with trimesh → `mesh.visual.uv` (GLB round-trip of UVs verified); overlap = `1 − unary_union(uv_triangles).area / Σ(tri.area)` via shapely (verified 0.0455 on a seeded overlap). shapely 2.1.2, BSD.
- **Texel-density variance**: per-face `sqrt(uv_area / 3d_area)`, report coefficient of variation (verified computation). 3D areas: `mesh.area_faces`.
- **Silhouette IoU vs input**: CPU-only orthographic raycast — `mesh.ray.intersects_any(...)` (engine `RayMeshIntersector`; needs `rtree`) → binary mask; IoU vs the background-removal-derived input alpha. Verified end-to-end at 64² (sphere fill 0.523; IoU sphere-vs-0.9-scale 0.817). No GPU, no renderer.
- **Critical eval nuance**: O-Voxel *intentionally* produces open surfaces and non-manifold geometry (upstream README "Arbitrary Topology Handling": open surfaces, non-manifold, internal structures). "Watertight=100%" is the wrong global target; metrics must be reported per input category with expected-topology tags (a leaf *should* be open). Upstream itself already fights hole defects: `m.fill_holes()` in decode (trellis2/pipelines/trellis2_image_to_3d.py:474), `mesh.fill_holes(max_hole_perimeter=3e-2)` ×3 in o-voxel/o_voxel/postprocess.py:110,144,157 — "fewer holes surviving upstream's own fill_holes" is the honest defect-fix claim.

## Perf + determinism metrics

- **Peak memory on MPS** — verified against PyTorch 2.13 docs (docs.pytorch.org/docs/2.13/mps.html): `torch.mps.current_allocated_memory()`, `torch.mps.driver_allocated_memory()`, `torch.mps.recommended_max_memory()`, plus `empty_cache()`, `synchronize()` (call before timing reads — MPS is async), `manual_seed()`, `get_rng_state()`/`set_rng_state()`. No `max_memory_allocated` equivalent on MPS → the harness samples `driver_allocated_memory()` per stage boundary (high-water tracking is DIY). CUDA side: `torch.cuda.max_memory_allocated()` as usual.
- **Wall-clock per stage**: mirror trellis-mac's stage table (pipeline load 103 s / sparse-structure 80 s / shape SLat 22 s / tex SLat 12 s / decoders ~27 s / bake ~15 s on M4 Pro 24 GB, `512`) — stage boundaries already exist in the pipeline call graph. Record cold vs warm separately; trellis-mac documents 6–10× thermal-throttle variance on Apple Silicon → the Mac battery needs a cool-down protocol and median-of-3 reporting, not single runs.
- **Determinism (seed plumbing, verified in source)**: `Trellis2ImageTo3DPipeline.run(image, num_samples=1, seed=42, ...)` (trellis2/pipelines/trellis2_image_to_3d.py:489–493) seeds **only** via global `torch.manual_seed(seed)` (line 538). All sampling noise draws use global RNG state — `torch.randn(...)` with no `generator=` at lines 208, 254, 299, 343, 412. No `torch.use_deterministic_algorithms` anywhere in upstream inference (grep over the repo: only train.py:36–39 seeds numpy/random, for training ranks). Consequence: same-seed reproducibility is plausible on one device/build but **not guaranteed** (and trellis-mac's `PYTORCH_ENABLE_MPS_FALLBACK=1` mixes CPU+MPS execution, further weakening it). Eval must *measure* determinism (same seed ×3 → vertex-count/hash + Hausdorff distance) rather than assume it; cross-device (MPS vs CUDA) bit-identity should not be claimed. The StableProjectorz fork confirms seed is the accepted API surface (api_spz/core/models_pydantic.py:18 `seed: int = Form(1234)`).

## Split execution: CI vs Mac

- **Cloud CI (no weights, no GPU)**: unit-test repair/report/metric stages on synthetic fixtures built in-code with `trimesh.creation` (icosphere/box) + seeded defects — all four verified above: (a) holed sphere (delete face cap), (b) non-manifold fin (extra triangle on an existing edge), (c) degenerate slivers (dup-vertex + 1e-9-offset triangles), (d) watertight interpenetrating concat. Each fixture has *known* metric values → assert exact counts (hole loops=1, NM edges=1, degenerate=2, SI faces=12). Also CI-testable: GLB export/UV round-trip, report formatting, silhouette-IoU math on analytic shapes, the API layer with a faked pipeline (mirrors TEE's adapter-fake pattern). Dep set is light: trimesh+rtree+shapely+numpy+scipy+pillow (+manifold3d, +pymeshlab dev-only).
- **Mac battery (real model)**: end-to-end on a fixed input set, both pipelines (`512` and `1024_cascade`), fixed seeds {0, 42, 1234}, metrics on the **exported GLB** (the canonical artifact — measure what ships, not the raw decode mesh).
- **Input image set (license-clean, failure-taxonomy coverage)**: (1) upstream's own examples — 72 .webp + T.png in assets/example_image/, distributed in the MIT-licensed repo, hash-named and version-pinned (use a fixed ~10-image "upstream-canonical" slice so results are comparable with anyone else's runs); (2) owner-shot photos (provable ownership) for: hard-surface prop (machined part), organic (plant/animal figurine), thin-structure (wire chair, stems), transparent object (glass bottle — exercises O-Voxel opacity), low-contrast background; (3) trellis-mac's shoe_input.png for cross-fork comparability. ## Baseline protocol (stock vs ours)

- One results file mirroring TEE's benchmarks/RESULTS.md: per row = input × pipeline-type × seed; columns = the defect metrics + stage timings + peak mem; two runs per row: **stock** (upstream 75fbf01 + minimal MPS enablement, defect fixes OFF) and **ours** (product path). Same machine, same session ordering, cool-machine protocol, median-of-3 for timings; geometry metrics from run 1 (they should not vary if determinism holds — the variance itself is a reported metric).
- Record in a frontmatter block: upstream commit, our commit, torch version, macOS version, machine, thermal state, pipeline type, seed list. Never overwrite — append dated sections.
- "Improved over stock" claims allowed only as deltas from this file: e.g. "NM-edge count p50: X→Y over the 20-image battery, seeds fixed".

## Implications for the build

- Vendor the fork now; pin `UPSTREAM_COMMIT=75fbf01`; treat upstream sync as a quarterly chore, not a design constraint. Do not plan around upstream PRs being merged.
- Build the metric module first, CI-only, on the four verified synthetic fixtures with exact-count assertions — it becomes both the test suite and the product's mesh-report feature (same code, TEE-style dual use).
- Defect metrics must be topology-aware: tag each battery input with expected topology (closed/open/mixed); score watertightness only where closed is expected; always score NM-edges, degenerates, self-intersections, UV overlap (defects regardless of topology).
- Determinism is a measured deliverable, not an assumption: same-seed ×3 identity check per release; fixing the global-RNG plumbing (pass `generator=` through the samplers) is itself a measurable "improved over stock" item.
- Perf harness: `torch.mps.synchronize()` + `driver_allocated_memory()` sampling at the existing stage boundaries; cool-machine protocol with median-of-3; report cold and warm separately.
- Results file = benchmarks/RESULTS.md clone with frozen input SHA256s, seeds {0,42,1234}, stock-vs-ours delta columns; every claim traces to a row.
- Keep pymeshlab (GPL3) and any NC-licensed data strictly out of the shipped product; eval-venv only.
