## The first relevant startup error

**There is none, and that is the finding.** From
`~/Library/Logs/Claude/mcp-server-TEE — Token Efficiency Engine.log`:

```
2026-09-10T12:32:14.738Z [info] Message from server: id=1 result   ← answering normally
2026-09-10T13:10:24.565Z [info] Shutting down server...
2026-09-10T13:10:24.565Z [info] Server transport closed (intentional shutdown)
```

Clean, deliberate shutdown. No error, no crash, and **no start attempted
since** — the log has not been written to since 13:10:24Z.

Timeline, from file timestamps:

| UTC | Event |
|---|---|
| 13:10:24 | server shuts down cleanly ("intentional shutdown") |
| 13:12:05 | new local bundle installed (`manifest.json`, `src/tee/**` written) |
| 13:12:20 | extension settings written with `isEnabled: false` |
| since | nothing — no startup, no error |

**Root cause: the extension is disabled.** `tee_status` and `tee_recall`
returned "unavailable" because nothing was running, not because anything
failed. The 15-second gap between the install and the disable flag is
consistent with Desktop disabling an extension pending owner review of an
update — offered as the likely reading, not asserted; I did not observe the
mechanism.

## Second defect, found in the same file

`project_root` is **`/Users/john/TokenEfficiencyEngine-a71`**. That directory
exists but has **no `.tee/config.toml`**. The checkout
(`/Users/john/TokenEfficiencyEngine`) does have one.

So re-enabling alone would start the server rooted at a directory with no
grants file — the failure research doc 66 records: it boots and silently
carries no mutation tier. This is the distinction section 2 of update 01 warns
about, realised in the live setting.

Both are owner-facing configuration:

1. re-enable the extension (a Desktop UI toggle), and
2. set the project folder to `/Users/john/TokenEfficiencyEngine`, or
   deliberately keep `-a71` and accept it has no grants.

I have changed neither. Enabling an extension and choosing a project root are
the owner's, and update 01 §2 says not to rewrite configuration for this
assignment.
