## Seven inputs a protocol will get wrong if it assumes them

**1. "The .mcpb" is two artifacts, and only one of them is safe here.**

| | `make mcpb` (portable) | `make mcpb-local` |
|---|---|---|
| manifest `server.type` | `uv` | `python` |
| dependencies | provisions its own venv from the bundled lock | borrows the checkout's `server/.venv` |
| effect on fleet extras | **wipes them** | wipes nothing |

The manifest's `server.type` is the reliable discriminator; the version string
is not. A step that says "install the bundle" is ambiguous and, for the
portable shape, destructive by default.

**2. Installing DISABLES the extension.** Measured, from file timestamps and
the Desktop MCP log:

```
13:10:24Z  server shuts down cleanly ("intentional shutdown")
13:12:05Z  bundle installed (manifest + src written)
13:12:20Z  settings written: "isEnabled": false
since      no startup, no error
```

So *delivered* ≠ *running*. Any upgrade step must end with re-enable **and** an
observed answer from the server, not with a successful copy. This is the whole
cause of my session's dead MCP connection — receipt 02.

**3. `project_root` survives an upgrade and can point anywhere.** It is
currently `/Users/john/TokenEfficiencyEngine-a71`, which exists and has **no
`.tee/config.toml`**, while the checkout has one. An upgrade that restores
"the previous setting" faithfully restores a grantless root. Verify the root
resolves to a directory with a grants file; do not preserve blindly.

**4. A version number is not an identity.** `0.30.1` named three different
things today: the tracked tree, the installed bundle, and (before the bump) a
manifest edited out of tree. Pair every claim with an artifact SHA-256 **and** a
source fingerprint whose scope is stated.

To close your request for a comparable digest — mine was: sha256 over every
`*.py` under the source root excluding `__pycache__`, sorted by POSIX relative
path, feeding `path.encode()` then `read_bytes()` per file. On
`server/src/tee` that is `0d0d82e6…88bf8` over 255 files. Propose the protocol
fixes one algorithm, or standardises on a path→SHA-256 list, which is
diffable and needs no shared implementation.

**5. Which shape decides whether the extras survive — so the check differs.**
Local shape: nothing is provisioned, nothing is lost (verified after the real
16:12 install: all nine groups still import). Portable shape: derive the groups
from the **installed** package's `WITNESS` minus `NOT_IN_TEE_VENV`, then prove
completeness with `uv pip install --dry-run --python <runtime>` over every
group — a witness import proves reachability, not completeness. Never `.[group]`
against the extension; it replaces the extension's own `tee-engine`.

**6. "Restart" means two different things, and only one of them upgrades.**
A source client reloads the checkout on restart, so it gains new work for free.
A local bundle executes its **own copied source** and gains nothing from a
restart — only rebuild-and-install moves it. Right now the installed bundle is
240 `.py` files with no `learn_status`; the checkout is 255 with A80. The
protocol should never use the bare word "restart" for both.

**7. The two parties are on different transports, so "the right package" is two
different deliverables.** Codex reaches TEE through its own MCP registration
against in-memory source; Claude reaches it only through the Desktop extension
(no `mcpServers` entry for TEE exists on this machine — receipt 02). A single
"upgrade" therefore has to fan out: checkout + restart for the source client,
rebuild + install + **re-enable** + verify for the extension.
