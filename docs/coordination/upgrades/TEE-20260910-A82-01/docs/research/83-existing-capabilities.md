# Headless architecture and cabinet lane — existing-capability map

Read-only source audit, 2026-09-11 local time. **Proposal, not an implementation or release.** The owner has specified a headless architectural application, a cabinet-making module, conversion from Unreal builds/meshes/LiDAR, worldwide jurisdiction coverage, and a GUI used when needed. Worldwide is the intended extensible scope, not a claim that every local rule is implemented today. A81 remains frozen; this draft changes no runtime, configuration, dependency or project state.

## Proposed common core and optional GUI

Use one standalone, headless building document and one command API, consumed by both TEE and the optional GUI. Store persistent semantic IDs and dependencies for site/frame → storeys → spaces/walls/slabs/roofs/openings, with cabinet assemblies and panels hosted by or positioned relative to those entities. Record commands, versions, edits and source provenance; derive B-reps, meshes, views and schedules as rebuildable products. The GUI selects entities and submits these same operations, with undo/checkpoints and no separate geometry authority. Keep graphical viewing optional and launch it only when requested.

Reuse partkiln's geometry behind a narrow service interface instead of adding architectural entities directly to its mechanical document initially. Extend TEE via `kernel/adapter.py:Adapter`/`LaneVocab`, `cli.py` lane construction/`attach_all`, and individual trust rows in `kernel/trust.py` and lane declarations in `kernel/lanes.py`. Preserve compact diffs, progressive tool discovery, jobs for long operations and the existing 17-tool core.

All incoming files remain immutable references. Conversion should produce **candidate** elements with source ID/hash, original transform/unit/frame, observation coverage, fit residuals and assumptions. Promotion to an authored wall/opening is a reviewable command. Never infer structural role, concealed thickness, fire rating, legal use or manufacturing detail solely from a mesh. Preserve unresolved geometry as reference geometry.

## Minimal implementation and subsequent phases

1. **Authoring vertical slice:** a single-storey compact building with a slab, joined walls, hosted door/window openings and a simple roof; one editable frameless cabinet with explicit panel thickness and shelf/door parameters. Changing width or wall position must regenerate dependent geometry, cutlist and views consistently. Save/reopen/replay must preserve identities and measured geometry. No GUI or scan recognition is needed to prove this core.
2. **Deliverable slice:** building plan/section/elevation, cabinet panel drawings, schedules/cutlist, IFC and visualization GLB. Verify IFC units, world geometry, openings, containment and IDs by independent readback; compare quantities against the native document. Add the optional GUI as another client of the same commands and state.
3. **Conversion slice:** begin with owner-labeled mesh components and scan-derived wall/plane candidates, using the existing control/registration pipeline. Add Unreal export with transforms, instances and source IDs, verified on a real project. Measure fit and uncovered regions against retained source geometry; allow correction/replacement without losing provenance.
4. **Cabinet fabrication and worldwide rule coverage:** extend explicit hardware/manufacturer rules, drilling, edges, tolerances and sheet nesting only as scoped; do not label a cutlist as CNC-ready. Start with a global country → region → municipality/authority selector and versioned rule-pack catalog. Resolve a project's location, authority, use, edition and conditions when applying a pack; do not block the jurisdiction-independent authoring/import/GUI core on universal rule acquisition. Complex roofs/stairs, renovation phases, MEP/structural workflows and collaboration are later scoped features rather than implied v1 coverage.

## Regional checks and evidence boundaries

`physical/plaus.py:check(model)` already selects region profiles and emits source-bearing findings, not approvals. Its rule data includes US/ZA/Namibian profiles, but some legal claims cite the imported knowledge base and the IRC span table carries `edition-verify pending`. **Do not inherit these assertions as verified local law or let its default US region silently choose the new project's regime.** Reuse the checking mechanism after primary-source re-verification for the actual jurisdiction.

Each new rule should name authority, source/edition/clause, adopted applicability, required model facts, units, measurement method and review status. The worldwide catalog must expose geographic, discipline and edition coverage, supersession and local amendments rather than equating a country label with completeness. Separate geometry correctness, information completeness/IDS, drafting practice and regulatory findings. Report `not_verified` for absent/unverified packs and `not_evaluated` for checks missing project facts; passing implemented checks does not certify the building. Existing joinery metadata likewise marks hinge and runner tables only partially verified, so manufacturer-specific details need fresh primary documentation before fabrication use.

Its binding metadata says Apache-2.0; the repository's separate OCCT notice/audit remains relevant. Do not co-install the two OCP wheel variants or run dependency sync as part of this proposal.

This audit inspected source and package metadata only. It ran no DCC, new geometry benchmark, standards check, dependency install or model request. Historical measured scan/CAD results remain in `docs/pointcloud-lane.md`, `docs/partkiln-lane.md` and their cited tests/research evidence; they do not measure the proposed building lane. Future validation should include negative controls for invalid/ambiguous inputs, measured unit/frame round trips, edit propagation, geometry/IFC reopen equality and absence of false compliance passes. Any changed runtime will need a new coordinated delivery and both actual-client receipts under the standing upgrade protocol.
