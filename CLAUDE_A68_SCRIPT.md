Research doc 52 parked OpenFOAM — *"Revisit only for a real airflow-engineering task"* — and doc 54 dispositioned OpenVSP as an asset source for boards, "NOSA lineage — run the lint before anything ships". What TEE adds that the four platforms lack is what TEE exists for: **one small, budgeted loop over all of them in which the model never sees a cell.** Every platform is driven out of process; results come back as coefficient tables, convergence verdicts and ≤64-row digests; pixels are opt-in; long solves are jobs. "Consolidate" means **the case directory is the interface**: a standard OpenFOAM case or SU2 `.cfg` from any source (CfdOF, a tutorial, a hand-made case, TEE's own writer) enters the same run → status → result → view loop. The GUI handoff is deferred, but everything it needs is left ready: the case directory and the `.foam` stub are what ParaView opens, the `.vsp3` is what OpenVSP opens, CfdOF-written cases are adopted headlessly. A67's ruling ("a viewer: CloudCompare is free and better") stands: TEE builds no viewer, ParaView is the viewer.

## Measured facts (2026-09-06 — build ON them; every number below was fetched from a primary source or measured in this container)

1. **OpenFOAM is GPL-3, and every Python bridge worth using is GPL too.** `foamlib` is `GPL-3.0-only` (PyPI `license_expression`), `PyFoam` GPL, `fluidfoam` GPL-3 — all BANNED for import; the lane writes its own dictionaries. `meshio` 5.3.5 is MIT (pure Python), numpy BSD — the only in-process helpers, inside the optional `[windtunnel]` extra. `pyvista`/`vtk`/`classy_blocks` were dropped on weight, not licence (docs 46/68 already ruled VTK "heavy; avoid").
2. **Two OpenFOAM forks, three dialects the lane may meet.** The owner's Mac gets openfoam.com **v2606** natively (`brew install gerlero/openfoam/openfoam` → `OpenFOAM-v2606.app`, binaries inside a read-only case-sensitive volume, entry script `/Applications/OpenFOAM-v2606.app/Contents/Resources/etc/openfoam`, cases on the normal filesystem). This container's apt ships openfoam.com **v1912** (`blockMesh snappyHexMesh simpleFoam pisoFoam pimpleFoam rhoSimpleFoam postProcess foamToVTK checkMesh surfaceFeatureExtract decomposePar reconstructPar foamDictionary`) and `openfoam-examples` puts the `airFoil2D` tutorial under `/usr/share/doc/openfoam-examples/examples/`. The Foundation's OpenFOAM-12 `forceCoeffs` dictionary shape is verified (patches, `rho rhoInf`, liftDir, dragDir, CofR, pitchAxis, magUInf, lRef, Aref); the coefficient OUTPUT file's name and columns differ by fork and version, so readers parse the header line.
3. **SU2 is LGPL-2.1, binary-only for this lane.** Release zips (serial + MPI) for Linux/macOS/Windows download from GitHub release assets (the HTML pages are blocked by this container's proxy; the asset redirect is not). **`pysu2` is not on PyPI** — it exists only in a source build with the wrapper enabled. The QuickStart `inv_NACA0012.cfg` keys are verified: `SOLVER= EULER`, `MACH_NUMBER`, `AOA`, `FREESTREAM_PRESSURE/TEMPERATURE`, `REF_ORIGIN_MOMENT_X/Y/Z`, `REF_LENGTH`, `REF_AREA`, `MARKER_EULER/FAR/PLOTTING/MONITORING`, `ITER`, `CONV_FIELD`, `CONV_RESIDUAL_MINVAL`, `MESH_FILENAME`/`MESH_FORMAT= SU2`, `TABULAR_FORMAT= CSV`, `CONV_FILENAME= history`, `VOLUME_FILENAME= flow`, `SURFACE_FILENAME= surface_flow`. Its mesh (485 KB) is a P0 calibration input, never a fixture.
4. **OpenVSP 3.51.3 is NOSA 1.3 and not on PyPI.** openvsp.org ships an Ubuntu 24.04 amd64 `.deb` (63.6 MB, downloaded here), macOS-14 ARM64 bundles pinned to **Python 3.11 or 3.13** (both of the Mac's venvs match one), and Windows. The bundled Python packages are MIT wrappers; the core is NOSA. `vspscript` (AngelScript) and `vspaero` are CLI binaries in the same bundle — the lane's primary route.
5. **ParaView is BSD-3 and ships `pvpython`.** 6.1.1 binaries: `…-MPI-Linux-Python3.12-x86_64.tar.gz`, `…-MPI-OSX11.0-Python3.12-arm64.dmg`; apt here has 5.11.2 + `python3-paraview`. Whether the apt build renders offscreen without a display is P0 row L6.
6. **CfdOF is LGPL-3.0** and needs OpenFOAM (Foundation 9–13 or OpenCFD 2006–2512), cfMesh, optional gmsh, HiSA. Documented as a GUI workbench with macro scripting; headless/RPC case writing is unknown (P0 rows C1–C3, Mac). TEE's one FreeCAD bridge is XML-RPC into the GUI (`server/src/tee/adapters/freecad/wire.py` `FreeCADWire.py_json`); the one-bridge rule (`docs/setup-freecad.md`) forbids a second.
7. **SimFlow** is proprietary freeware whose site blocks non-browser fetches; nothing about it could be verified here (Mac row S1). Disposition: not integrable as software; a standard OpenFOAM case it writes is adoptable like any other.
8. **The kernel's `JobManager.cancel` is cooperative only** (`server/src/tee/kernel/jobs.py:254-264`: "Running: cooperative only - the DCC-side operation finishes but its result is dropped"). A cancelled two-hour `simpleFoam` would keep four cores busy — hence D5's `on_cancel` hook.
9. **`RESERVE_GB = 16.0`** (`kernel/machine.py:51`) exceeds this container's 15 GB: with the QoS law on, `may_admit` would refuse every job here. Tests set `TEE_MACHINE_TOTAL_GB`; the law is off by default.

### D3. The case directory is the interface
An OpenFOAM case is `system/controlDict` (solver = `application`); an SU2 case is a `.cfg` with `MESH_FILENAME=`; an OpenVSP model is `<Vsp_Geometry>`. Adoption copies into the store with source path + hash and never mutates in place. Fork detection decides the writer dialect and the reader's expected names — the list measured in P0; anything else refuses `wt_fork_unsupported`. **TEE never executes a case's own `Allrun`/`Allmesh`**: it parses `runApplication <binary>` lines and runs those known binaries with argv it composed (the pipeline lane's argv-only law, `pipeline/schema.py:22`).

### D4. The fidelity ladder (`fidelity.choose`, a tested table)
`airfoil2d` + viscous or M < 0.3 → `rans` (SU2 SA/SST on the O-mesh; OpenFOAM if SU2 absent) · `airfoil2d` inviscid, 0.3 ≤ M < 1.2 → `euler` (SU2) · `wing3d`, M ≤ 0.6, AoA ≤ 10° → `panel` (VSPAERO) · `wing3d` viscous / M > 0.6 / AoA > 10° → `rans` (OpenFOAM snappy on the exported STL) · `body3d` → `rans` (OpenFOAM) · adopted → its own. Every `wt_case create` answer carries `fidelity:{chosen, reason}`; an override the ladder considers wrong runs, and the uncertainty label says `not-predictive`.

### D5. Jobs, ledger, cancel, orphans
`ENGINES` rows `cfd-mesh` (floor 2 GB), `cfd-solve` (floor 4 GB; per-run override from cells × measured bytes/cell), `aero-panel` (0.5 GB, `qos_default="standard"`); `cost.wall_s` from P0. Register → submit (with `try/except TeeError: release; raise`) → release in the worker's `finally`, exactly `capture/tools.py:378-404`. Cost model `est_wall_s = cells × iters × k_engine / cores` with dated `k`; the gate decides only whether to ASK; actual wall time is written back to `case.json` and reused. Timeout `max(2 × est, 600)` capped by `[windtunnel] max_wall_s` (14 400) → state `timeout`, `wt_result` reads what exists. **Cancel**: `JobManager.submit(..., on_cancel=run.terminate)` — a 12-line kernel change: the hook is stored per job, invoked once outside the lock when a running job is cancelled, dropped on prune and in the worker's `finally`; queued jobs need none. **Orphans**: `run.json` pid + liveness + cmdline check → `wt_status` says `orphan`; `wt_case action=stop` kills after verification. A registered solve blocks LLM engine swaps (`may_swap`) — documented, never bypassed.

## Laws (A53's ten and CLAUDE.md's six hard rules stand by reference; these are this lane's)
1. **The model never sees a cell**: points, fields, meshes and solver logs stay on disk; digests only — no array over 64 elements, no string over 2 KB, tested.
2. **No bare coefficient**: engine, version, mesh hash, verdict and uncertainty travel with every number.
3. **CFD is comparative before it is absolute** (DPW): same-mesh deltas are first-class; absolute values always carry the label.
4. **Cheapest capable engine first**, and the router says why; overridable, tested.
5. **Copyleft at arm's length, nothing downloaded, nothing vendored**; the gate is a test, and every golden carries a `generated-by` line.
6. **Read the header, detect the fork** — never the column index, never an assumed dialect.
7. **A tool call never waits on a solver**; cancel means the process is dead, measured.
8. **ParaView is the viewer**; TEE builds none; pixels are opt-in and captioned with numbers.
9. **The case directory is the interface**; adopted cases are copied, never mutated; TEE never runs a case's own scripts.
10. **Zero always-loaded tools; every `wt_*` tabled individually; no family row.**
11. **A reference is not a tolerance until verified at source**, with URL and date, or `wt_verify` refuses it.
12. **Measured before and after** (A53 law 1): a phase without a number did not happen; Mac numbers come from the Mac, never from here.

### Amendments learned while building (2026-09-06; the script is amended, not improvised around)
- **P0 L1/L1b:** Ubuntu's apt `openfoam` 1912 cannot report a force (every function object dies on an IOstream "sha1" error); the container measurements and the Linux install line moved to openfoam.com's `openfoam2606-default`, and `engines._foam_candidates` searches `/usr/lib/openfoam/openfoam*` first and `/usr/share/openfoam` last.
- **P0 L4:** `cores > 1` ships (1/2/4 cores: 7.8/6.8/4.8 s on the 16,000-cell case). Open MPI refuses to run as root: `runs.mpi_env` sets the two `OMPI_ALLOW_RUN_AS_ROOT` variables for root and a parallel run only, and the run record says `mpi_root_override`.
- **P0 L12:** not possible in the container (no local LLM); the ledger-coarseness risk stays open for the Mac.
- **P1 verdict:** `SCALE_FLOOR` (cl 0.1 / cd 0.01 / cm 0.01) — the stationarity test is relative above the floor and absolute below it, because a relative test on Cm ≈ 5e-4 flagged a converged run `insufficient`.
- **P1 mesh:** every mesh directory gets `system/{controlDict,fvSchemes,fvSolution}` stubs (`foam.write_mesh_system`) because `checkMesh` and `blockMesh` insist on them; `TOLERATED_CHECKS = ("skew", "upper triangular")` are the two single checkMesh failures a run proceeds through (the TE seam of a sharp section; the apt tutorial's face ordering).
- **P1 runner:** the run registry is keyed `case/run` (run ids restart per case); `wt_already_running` asks the job manager, not only the process registry; a refused submission marks its runs `refused`; a crashed solver is a failed job (`wt_solver_failed`) for a single run and a marked point in a sweep; an exit code the reader overrules (vspscript exits 2 after a complete sweep) is recorded as `exit_code_overruled`.
- **P1 geometry:** `omesh` takes the first cell in METRES and normalises by the chord itself (the caller divided twice; a 1 m chord never showed it); `wt_case` removes the empty `geometry/` directory before moving the temporary one in (`shutil.move` INTO an existing directory nests).
- **P1 3-D:** the default background cell is L/4, not L/8 (the surface levels do the refining; L/8 made a 2 M-cell background for a 0.3 m body).
- **P1 fields:** `wt_probe_field` returns a vector's magnitude by default (`components=true` for x/y/z: four arrays of 64 cost 929 tokens); samples with `vtkValidPointMask` 0 are `null` and counted in `outside_mesh`.
- **P2 adoption:** an adopted case with a mesh is checked, not re-meshed (`remesh=true` reruns its sequence); it runs its OWN dictionaries and solver (`prepare_adopted_openfoam_run` copies `system/`, the properties and `0/` into the run copy and links the mesh); without a `forceCoeffs` entry the result is a residual-only verdict with `cl/cd/cm = None`; **`wt_run forces={patches, lRef?, Aref?, U?, CofR?}`** adds the function object to TEE's run copy with the chord MEASURED from the wall patch (`foam.patch_bbox`) — lRef 1 on the apt tutorial's 35 m section gave Cl 34, the mesh gives 0.970 at α 8°.
- **P2 dialect:** `wt_fork_unsupported` is raised by `_Lane._openfoam(for_writer=True)` (a TEE-written case or a snappy mesh on a Foundation install); adopted cases pass `for_writer=False`.
- **P5 search:** the recall table re-measured at 98 tools and 42 cases: 40/42 at 3 (the old witness slid to rank 5; "which cfd solver is running" → `wt_status` is the new rank-4 witness), 42/42 at 5.
- **P5 benchmark:** measured on the fakes, whose files match the real ones in shape and per-iteration size: TEE 2,796 tokens / 15 calls vs naive 19,145 / 16 (85.4 % saved); the real-engine per-call costs are in doc 70 §3.5.
- **P6 kernel law:** a 15 GB container refuses every job engine under the 16 GB reserve; `TEE_MACHINE_TOTAL_GB` declares capacity and the setup doc says so.
